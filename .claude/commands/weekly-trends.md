# 이번 주 데이트 트렌드 조사 (C 파이프라인)

"이번주 데이트" 앱의 주간 추천에 섞을 **이번 주 국내 데이트 트렌드**를 조사해 JSON 파일로 만든다.
A 파이프라인(TourAPI)이 놓치는 팝업스토어·신규 전시·화제의 장소를 보완하는 것이 목적이다.
사용자 추가 요청: $ARGUMENTS

## 1. 이번 주 확인

```bash
npm run --prefix scripts trends -- info
```

주차(weekId), 기간(월~일), 계절, 파일 경로를 확인한다. 파일이 이미 있으면 사용자에게 덮어쓸지 추가할지 묻는다.

## 2. 조사

WebSearch / WebFetch 로 **이번 주(월~일)에 실제로 갈 수 있는** 데이트 장소·행사를 찾는다.

- 대상: 팝업스토어, 새로 열린 전시·공연, 시즌 명소(단풍·벚꽃 등 계절에 맞게), 화제의 축제, 블로그·뉴스에서 언급이 많은 신상 카페·거리
- **권역을 고르게**: 수도권(서울·인천·경기), 강원, 충청(대전·세종·충북·충남), 전라(전북·전남광주), 경상(부산·대구·울산·경북·경남), 제주 — 권역마다 최소 1개, 전체 12~20개
- 제외: 광고성 협찬 글만 있는 곳, 운영 여부를 확인할 수 없는 곳, 이번 주 전에 끝났거나 90일 뒤에 시작하는 행사, 성인 전용·유흥 업소

## 3. 교차 확인 (필수)

항목마다 **공식 홈페이지·공식 SNS·언론 기사·예약 페이지** 등 출처를 직접 열어 다음을 확인한다.

- 날짜: 시작일·종료일 (상시 운영이면 period 는 null)
- 장소: 정확한 장소 이름과 주소 (시·도, 시·군·구)
- 운영 여부: 이번 주에 문을 여는지 (휴관일, 사전 예약 필수 여부는 summary 에 적는다)

**출처로 확인되지 않은 정보는 추측해서 채우지 말고 그 항목을 뺀다.** 출처는 가능하면 2개 이상, 최소 1개.

## 4. 파일 작성

`data/trends/{weekId}.json` 을 아래 형식으로 쓴다. 좌표(lat/lng)는 비워 두고 5단계에서 채운다.

```json
{
  "weekId": "2026-W40",
  "generatedAt": "2026-09-28T10:00:00+09:00",
  "courses": [
    {
      "id": "2026-W40-C-001",
      "kind": "irregular",
      "title": "성수 ○○ 가을 팝업스토어",
      "summary": "한정 굿즈와 포토존, 주말은 현장 대기 1시간 이상",
      "themes": ["전시·공연"],
      "sido": "서울",
      "sigungu": "성동구",
      "period": { "start": "2026-09-26", "end": "2026-10-12" },
      "stops": [
        { "order": 1, "name": "○○ 성수", "type": "event", "addr": "서울 성동구 연무장길 00", "url": "https://공식페이지" }
      ],
      "sources": ["https://공식페이지", "https://기사"],
      "seasonNote": "가을 한정"
    }
  ]
}
```

- `id`: `{weekId}-C-001` 부터 순서대로
- `kind`: 기간 한정이면 `irregular`(period 필수), 상시면 `regular`(period 는 null)
- `themes`: 다음 중에서만 1개 이상 — `맛집·카페`, `전시·공연`, `액티비티·체험`, `자연·산책`, `축제·시즌 이벤트`, `실내(비 오는 날)`, `드라이브`
- `sido`: 서울·부산·대구·인천·대전·울산·세종·경기·강원·충북·충남·전북·전남광주·경북·경남·제주 중 하나 (광주·전남은 `전남광주`)
- `stops`: 메인 장소 1곳이면 충분하다. 업로드할 때 A 와 같은 규칙으로 주변 식당·카페가 자동으로 붙는다.
- `title`: 80자 이하, 앱 카드 제목으로 그대로 보인다
- `seasonNote`: 계절·한정 문구가 있으면 짧게, 없으면 null

## 5. 좌표 채우기와 검증

```bash
npm run --prefix scripts trends -- geocode data/trends/{weekId}.json
npm run --prefix scripts trends -- validate data/trends/{weekId}.json
```

- geocode 는 카카오 장소 검색으로 좌표·주소를 채우고, 찾은 장소 이름을 보여 준다. **찾은 이름이 의도한 장소와 다르면** 이름을 더 구체적으로 고치거나 좌표를 직접 넣고 다시 실행한다.
- `KAKAO_REST_KEY` 가 없다는 오류가 나면 사용자에게 알리고, 카카오맵 장소 검색 도구가 있으면 그것으로 좌표를 넣는다.
- validate 가 오류 없이 통과할 때까지 고친다.

## 6. 요약하고 확인받기

사용자에게 표로 보여 준다: 권역, 제목, 기간, 테마, 출처 수. 권역 분포와 빠진 권역이 있으면 이유도 적는다.
그리고 **"이대로 올릴까요?"** 라고 묻고, 사용자가 승인하기 전에는 커밋하지 않는다.

## 7. 올리기 (승인 후)

```bash
git add data/trends/{weekId}.json
git commit -m "트렌드: {weekId} (N개)"
git push
```

push 하면 GitHub Actions `트렌드 업로드` 워크플로가 검증 후 Firestore 에 합친다.
끝나면 앱의 이번 주 탭에서 "최신 코스로 다시 추천받기"를 누르면 트렌드 코스가 추천 후보에 들어간다고 안내한다.
